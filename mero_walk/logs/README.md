# 실물 걷기 로그

`mero run`이 걷기마다 남긴 로그예요(`walk_*.csv` + 같은 이름의 `.json`). 열 설명은 `../README.md`의 "걷기 로그"를 보세요.

**파일 이름의 날짜·시간은 믿지 마세요.** 로봇(오렌지파이)에는 RTC가 없어서 재부팅할 때마다 시계가 2026-11-19 08:17쯤으로 돌아가요. 그래서 2026-11-20에 돌린 걷기도 `20261119_0817…`처럼 찍혀 있어요. 어떤 정책으로 돌렸는지는 `.json`의 `policy`, `gyro_frame`으로 확인하세요.

## 자이로 버그 (2026-11-20 수정)

이 로봇의 IMU 칩은 원본 microban과 다른 방향으로 달려 있어요(`mount_quat` (0.5, 0.5, −0.5, −0.5), 원본은 (0.5, −0.5, −0.5, 0.5)). 그런데 수정 전 런타임은 `walk.onnx`(`gyro_frame=imu`)에 칩의 자이로 값을 그대로 넣었어요. 그래서 pitch와 yaw 각속도 부호가 반대로 들어갔어요. 수정 후에는 몸통 자이로를 원본 IMU 프레임으로 돌려서 넣어요(`mero/controller.py`).

| 구분 | 로그 | 특징 |

| 수정 전, `walk.onnx` | `082823`, `082948`, `085842`, `085913`, `085930`, `090507` | 속도 0에서도 목표각이 16–68° 흔들리고 0.5–12초 안에 넘어짐 |
| `mero_walk_dr.onnx` (`gyro_frame=body`, 버그 영향 없음) | `081938` | 1초 만에 오른쪽으로 44° 기욺. 오른쪽 무릎이 하중을 받은 채 펴지지 않음. 전원이 끊겨 `.json`이 빈 파일 |

## 알려진 문제

- **전원:** 걷다가, 가만히 서 있다가도 전원이 끊기고 재부팅돼요. 그런 로그는 `event` 열에 정지 메시지가 없고, 상태가 `WALK`인 채로 끝나요. `081827`은 끝에 붙어 있던 NUL 바이트(전원 차단 흔적)를 잘라냈어요. 지금 런타임은 0.3초마다 디스크에 저장해서, 전원이 끊겨도 마지막 0.3초 정도만 잃어요(`082003`까지는 1초 간격).
- **오른쪽 다리:** 서 있을 때 오른쪽 엉덩이 roll(22번)과 발목 roll(26번)이 왼쪽보다 명령 각도에서 더 처져요(`081827`, `081859`: 3.3° vs 0.1–0.3°, 6.4–7.7° vs 2.2–3.6°).
